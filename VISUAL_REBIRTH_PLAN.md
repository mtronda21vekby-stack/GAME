# CROWN//FRONT Visual Rebirth Plan

## Shipping baseline

- Unity `6000.5.3f1`, Built-in render pipeline, IL2CPP WebGL.
- Production version before this stage: `0.2.0-alpha.2`.
- Shipping scene is generated by `CrownEngineCloudBuild.RebuildPrototypeScene()` at `Assets/_Project/Generated/CrownEngine_Prototype.unity`.
- The generated scene contains one gameplay root, `CrownEngineGame`; runtime code builds the camera, arena, cores, towers, units, projectiles, impacts, and IMGUI HUD.
- Baseline public CROWN//FRONT payload: approximately 4.8 MiB.
- Gameplay values and decision logic are concentrated in `CrownEngineGame.cs` and must remain unchanged.
- No checked-in prefabs, authored materials, VFX assets, EditMode tests, or PlayMode tests existed at audit time.

## Main visual problems

- Arena geometry is a flat set of repeated cubes with little foreground/background separation.
- Core and towers are simple cylinders without a unified mechanical hierarchy.
- Unit roots and visual geometry are not separated; silhouettes read as capsules and cubes.
- Projectiles and impacts allocate and destroy objects for every shot.
- Materials depend on runtime shader lookup and have no coherent authored shader language.
- HUD uses large opaque IMGUI boxes and generic buttons.
- Camera has titan motion but no dedicated presentation rig or event feedback.

## Implementation phases

1. Preserve the existing generator and gameplay root; back up changed Unity files.
2. Add a WebGL-safe instanced CROWN//FRONT surface shader and shared palette.
3. Rebuild the titan body and arena as layered armor, recessed mechanisms, conduits, bridges, vents, and structural masses while retaining lane X coordinates.
4. Rebuild Core and tower presentation with visual-only child hierarchies, rotating parts, team energy, recoil, damage, and destruction states.
5. Rebuild Assault, Tank, and Raider visual roots with layered armor and procedural animation while preserving unit stats and movement roots.
6. Replace per-shot projectile/impact allocation with prewarmed pools and add restrained trails, sparks, shock rings, and debris presentation.
7. Add camera settle, breathing, major-impact shake, and result framing without changing gameplay input or rules.
8. Restyle the existing HUD while keeping the battlefield center clear and retaining card/tap deployment.
9. Add editor validation for hierarchy, forbidden strings, materials, scene generation, and missing scripts.
10. Build and validate a `0.3.0-alpha.3` review artifact before any production payload replacement.

## Performance guardrails

- Shared materials only; no per-instance material cloning.
- GPU instancing enabled on the common opaque shader.
- Exactly one realtime Directional Light; Core accents are emissive geometry rather than extra lights.
- No post-processing package, realtime reflection probes, cloth, HDRP, or fullscreen effects.
- Prewarmed projectile/impact/debris pools; no Instantiate/Destroy for normal shots.
- Opaque geometry preferred; transparent presentation limited to short pooled effects.
- Physical-device FPS remains a manual requirement and will not be estimated.
